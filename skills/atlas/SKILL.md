# atlas

atlas keeps a text model of a repo's elements (boxes) and relations (arrows) as YAML next to the code. Read it before
you change code; update it in the same change when you add, move or remove a part.

Status: seed. The `atlas` CLI is built from the evocaslab/hq repository until the code moves into this repo; format
reference: `docs/format.md`.

## When to use

- A repo contains `atlas.yaml` (or `docs/atlas/atlas.yaml`): the model exists, read it first.
- You need to know which element owns a file, crate or service, or what depends on it.
- You change structure (new crate, service, table, dependency): the model must change with it.

## Steps

1. Find the workspace: `atlas.yaml` with `elements/`, `relations/`, `views/`.
2. Read the element whose `sources` tags match the file you will touch, then its relations (`from` / `to`).
3. After the change, add or edit the element and relation files; ids use only `a-z 0-9 . -` and the file name is the id.
4. Run `atlas check <dir>` when the CLI is available: it validates the files and the drift between model and code.
   A drift error names the element and the missing source; fix the model or the code, never delete the check.

## Rules

- Only edit atlas YAML files; the skill runs no scripts and fetches nothing.
- Unknown keys are errors by design: do not invent fields, see `docs/format.md`.
- A `draft: true` model was generated by `atlas init`; treat it as a starting point, not as truth.
